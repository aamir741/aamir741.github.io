CISA Domain 5.16: Domain 5 Recap, Memory Aids and Exam Traps

CISA Domain 5.16 recap: memory aids for identity, cryptography, PKI and response, look-alike terms, the common exam traps, decision owners and control purpose.

Muhammad Aamir · 29 November 2026

A login asks for a password and the answer to a security question, and management calls it multi-factor authentication. Is it? On the CISA exam, no, because both are something you know. This lesson is CISA Domain 5, Section 5.16, the last mile: memory aids and exam traps for the whole of Domain 5, and the close of the course.

Memory aids

Use these after reading the explanations. They help recall distinctions, but the asset, threat, timing and stated objective still decide the answer.

Prompt What to remember
CIA: disclosure / alteration / interruption Several can be affected together
Claim, prove, permit, trace Identification, authentication, authorization, accountability
Know / have / are Different factor types; two passwords are not MFA
FAR admits the wrong person; FRR rejects the right person Compare CER/EER under comparable conditions; assess thresholds and fallback
Owner directs; custodian implements Assign business accountability and operational duties
Sign with mine; verify with mine Private key signs, trusted public key verifies; it does not conceal the message
Encrypt for them The recipient's public key protects content for the recipient's private key
CA issues; RA verifies; repository publishes Separate certificate roles
Revocation changes trust, not the key's mathematics CRL or OCSP communicates status
A digest needs a trusted comparison An unkeyed hash alone does not establish source authenticity
DLP needs meaning and coverage Sensitive information, permitted use, channels, response
Find, demonstrate, monitor, respond Assessments, penetration tests, detection and response supply different evidence
Preserve, verify, analyze, explain Protect sources, validate copies, document conclusions and limits

Term check: WORM retention differs from a malware worm, and a scanned signature differs from a cryptographic signature. Separate enrollment failure, false rejection and false acceptance, and define event, alert and incident before deciding how to respond.

Exam traps

Tempting wrong answer Exam answer
Encryption always guarantees integrity Authenticated encryption, trusted hashes, MACs and signatures give integrity-related evidence
A digital signature keeps a message confidential Signing supports integrity and non-repudiation; confidentiality needs encryption
Any matching hash authenticates the download Trust the expected digest or an authenticated signature or MAC
OCSP always proves current validity in real time Verify responder authority, signature and freshness
Every CA is the root trust anchor Intermediate CAs can issue; the accepted root anchors the chain
The directory server issues certificates The CA issues and signs, the RA verifies, the directory distributes
OAuth alone is user authentication OAuth delegates authorization; OpenID Connect adds identity
Two passwords count as MFA MFA needs different factor types
File owners can override mandatory access labels MAC is system-enforced, DAC is owner discretion, RBAC is by role
False rejection is the security-critical biometric error False acceptance directly admits impostors
A public web server belongs on the internal network Isolate public services; IDS detects, IPS can block
Technical filters alone stop social engineering Combine awareness, independent verification and technical safeguards
A zero-day is fixed by installing the patch now A patch may not exist; reduce exposure and use compensating controls
SQL injection and XSS have identical defenses Parameterization versus context-aware encoding
A contract alone secures the cloud Verify provider assurance and your own identity, configuration and data controls
Device tracking protects lost mobile data Enforce encryption and protected keys; remote wipe complements them
A passed audit or clean scan proves complete security The conclusion is bounded by scope, criteria, methods, evidence and time
Notify customers or restore before containing Authorized containment is urgent for confirmed ongoing harm; run evidence and communications in parallel
Chain of custody guarantees court acceptance It supports but does not guarantee admissibility
Deploy DLP or encryption before classifying data Establish owners, objectives and handling rules first
A vulnerability scan proves exploitability Penetration testing can demonstrate exploitation within scope

Decision owners and control purpose

The business or data owner defines sensitivity and justified use; security and IAM teams implement and monitor controls and protect privileged bypass paths; the CA issues, the RA verifies and the relying party decides reliance; the CSIRT and authorized management coordinate incident response, while audit assesses readiness without owning it.

Controls work together as preventive, detective and corrective, depending on how they are configured and used. For credential misuse, data disclosure and malicious alteration, pair suitable prevention (authentication, classification-based access, controlled changes) with detection (monitoring, DLP, trusted verification) and correction (contain, assess, restore a validated state).

Practice questions

1. A user compares an installer's hash with a value on the same download page. Which statement is MOST accurate? Answer: the expected digest needs a trusted source, or a signature.

2. A company wants to deploy DLP but has not classified its data. What should the IS auditor recommend FIRST? Answer: establish data owners, protection objectives and handling rules.

3. A laptop with customer data is lost and management relies on device tracking. What is the BEST response? Answer: confirm encryption and protected keys were enforced on the device.
