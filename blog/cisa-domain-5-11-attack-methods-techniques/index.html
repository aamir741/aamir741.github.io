CISA Domain 5.11: Information System Attack Methods and Techniques

CISA Domain 5.11: passive vs active attacks, fraud risk factors, network, identity, application, password and transaction attacks, malware, zero-days, ransomware, reconnaissance and generative AI risks.

Muhammad Aamir · 28 November 2026

A visitor posts a comment on a website, and it runs as a script in every other visitor's browser. Is the fix a faster database query or stronger encryption? On the CISA exam, you choose the defense that matches the attack mechanism. This lesson covers CISA Domain 5, Section 5.11.

5.11 Threats and attacks

A threat is a circumstance or event with the potential to cause harm. An attack is an attempt to exploit a weakness or bypass a safeguard. Passive attacks observe; active attacks change, impersonate or disrupt. For any method ask what it targets, how it reaches the target, and which controls can interrupt it.

Fraud risk factors are pressure, opportunity and rationalization. Computers can be targets, tools or repositories of evidence. Assess collusion and management override as well as individual access.

5.11.2 Network, identity and social-engineering attacks

Attack Control direction
Eavesdropping / sniffing Appropriate encryption, endpoint protection, physical safeguards
Traffic analysis Limit exposed metadata
Man-in-the-middle Authenticated protocols, correct certificate validation
Replay Fresh challenges, nonces, bounded lifetimes, enforced by the receiver
Session hijacking Protect tokens and sessions; reauthenticate sensitive actions
IP spoofing Anti-spoof filtering; IP alone is weak identity
Phishing, spear phishing, whaling, smishing, vishing Layered messaging controls, reporting, robust authentication, independent verification
Pharming / DNS spoofing Protect resolution; validate service identity
Watering hole Secure browsing, updates, supplier vigilance
DoS / DDoS, reflection Capacity, filtering, rate controls, anti-spoofing, upstream mitigation
Tailgating / pretexting Controlled entry, verification, reporting

5.11.3 Application, password and transaction attacks

  • SQL injection: untrusted input changes database command meaning. Use parameterized queries, validation and least-privileged access.
  • XSS: untrusted content runs as script in a browser. Use context-appropriate output encoding and safe templating.
  • CSRF, buffer overflow, race condition (TOCTOU), URL manipulation: anti-CSRF protections, memory-safe design, atomic operations, server-side authorization on each resource.
  • Brute force, dictionary, password spraying, credential stuffing, rainbow tables: rate controls, compromised-password checks, unique credentials, MFA, unique salts and costly derivation.
  • Privilege escalation, salami, data diddling, DNS tunneling: patching, least privilege, reconciliation, independent review, resolver controls and egress restrictions.

SQL injection and XSS do not have identical primary defenses, and a generic "input validation" answer can be less direct than the control that targets the stated execution context.

5.11.4 Malware and targeted intrusion

A virus infects host content, a worm self-propagates, a Trojan looks legitimate, spyware and keyloggers collect information, a rootkit conceals presence, a logic bomb triggers on a condition, a backdoor bypasses access, a botnet is a set of controlled compromised devices and cryptojacking misuses resources for mining. An advanced persistent threat is sustained, targeted activity, not one malware family. A zero-day targets a weakness before an effective patch is available, so reduce exposure and use compensating controls. Patching does not prevent every worm or unknown exploit, and "antivirus is always useless against zero-days" is too broad.

Defend in layers: secure configuration, reduced exposure, supported updates, application control, behavior-based detection, segmentation and isolated, recoverable backups.

5.11.5 Ransomware and control selection

Coordinate containment, evidence, credential protection, clean recovery and impact assessment, and consider theft as well as encryption. Payment does not guarantee recovery, deletion of stolen data or freedom from further attack.

Reconnaissance and modern attack paths

Port scanning finds reachable listeners, war driving finds wireless networks in range, war dialing finds modems that answer, and dumpster diving and shoulder surfing gather discarded or observed information. Discovery is not a confirmed vulnerability or compromise, and testing needs authorization and agreed scope. ARP poisoning actively manipulates local address resolution.

For generative AI, prompt injection brings adversarial instructions in through input or retrieved material, data poisoning manipulates training or retrieval sources, and sensitive data can leak through prompts, outputs, logs or provider retention. Enforce data and action permissions outside the model.

Practice questions

1. A visitor's comment runs as script in other visitors' browsers. Which control MOST directly addresses this? Answer: context-appropriate output encoding when rendering. Parameterized queries defend against SQL injection, not XSS.

2. A zero-day exists in a widely used server component and no patch is available. What is the BEST course of action? Answer: reduce exposure and apply compensating controls until patched. A patch that does not exist cannot be installed, and waiting leaves full exposure.

3. Ransomware encrypts file servers and the attacker claims to have copied customer data. Which approach is MOST appropriate? Answer: containment, recovery and impact assessment must cover data theft too. Payment guarantees nothing and a restore does not undo theft.
