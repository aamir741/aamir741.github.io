CISA Domain 4.11: Database Management

CISA Domain 4.11: DBMS architecture and metadata, database models, integrity, ACID, concurrency, normalization, DBA controls, data governance, and testing integrity and recovery.

Muhammad Aamir · 28 November 2026

An application checks that every payment references a valid customer, but a bulk loading utility loads thousands of payments and skips the check. Is the database protected? The control has to cover the actual data entry routes. This lesson covers CISA Domain 4, Section 4.11: how an IS auditor evaluates database design, integrity controls, administrator privileges, recovery and data governance.

4.11 What a DBMS does

A database management system (DBMS) organizes and controls data storage, retrieval and change. It can provide access control, transaction processing, integrity constraints, concurrency and recovery, but its capabilities depend on correct design, configuration and use.

4.11.1 Architecture and metadata

Schemas describe how data is organized and constrained. A data dictionary or catalog records metadata such as tables, fields, types, keys and relationships; keep authoritative definitions and restrict changes. Data independence reduces the need for applications to know physical storage details, but does not remove dependence on data meaning.

JDBC is the Java API for database access through suitable drivers; an API is the general concept. Review connection credentials, driver configuration, query construction, privileges and transaction handling.

4.11.2 Database structure

A relational database (RDBMS) organizes data in tables related through keys and is queried with SQL. It is one type of DBMS.

Model Organization
Hierarchical Tree-like parent and child structure
Network Records in multiple linked relationships
Relational Tables linked through keys, queried with SQL
Object-oriented Objects and their behavior
NoSQL Key-value, document, wide-column and graph approaches

NoSQL transaction and consistency guarantees vary by product and configuration.

4.11.3 Database controls

  • Entity integrity: a unique, non-null primary key.
  • Referential integrity: valid relationships, often via foreign keys.
  • Domain integrity: allowed types, ranges and values.

A valid key does not prove that a transaction was genuine or authorized. ACID stands for atomicity, consistency, isolation and durability. Commit makes a transaction's changes final; rollback undoes uncommitted work. Test isolation and recovery for the actual configuration rather than assuming every database offers identical guarantees.

Normalization reduces redundancy and update anomalies; denormalization intentionally adds redundancy, often for performance, and needs consistency controls. Restrict direct data changes, powerful utilities and administrator access. The database administrator (DBA) maintains the platform, while business owners remain accountable for data meaning, classification and authorized use.

4.11.4 Reviews and data governance

Review roles, privileged activity, schema changes, constraints, patching, backups, restoration, performance and encryption and key dependencies. Independently monitor sensitive DBA actions where practical. Select evidence by control objective: audit logs can detect unauthorized activity, constraints prevent particular invalid states and transaction logs support recovery.

Data governance assigns ownership, stewardship, standards and quality responsibilities. Define and measure accuracy, completeness, consistency, timeliness and lineage. A technically valid database can still contain wrong business information, so trace important reports through source data, transformations, exceptions and review.

Auditor perspective: integrity, concurrency and recovery

Concurrency anomalies include dirty reads, nonrepeatable reads, phantoms and lost updates. Locks, version checks and snapshot mechanisms behave differently, so verify the actual product, isolation level and configuration. A deadlock occurs when transactions wait on one another in a cycle and cannot progress without intervention; review detection and timeout or retry behavior. Some systems use spool space for temporary query results, and quotas can limit resource exhaustion.

Example: a process commits a payment record, then fails before receiving an external bank acknowledgment. Local durability does not prevent a duplicate payment on an unsafe retry. Evaluate end-to-end identity, reconciliation and exception handling, plus DBA access, change, auditability, backup and tested recovery to a consistent point.

Example: a bulk loading utility bypasses the rule that each payment references a valid customer. Determine whether the database or another safeguard covers the load. Inspect authorization for the utility, exceptions and post-load reconciliations, test loaded records against reference data, and consider whether a failed batch can be recovered consistently.

Practice questions

1. An application checks each payment references a valid customer, but a bulk loading utility bypasses the check. What should the IS auditor do FIRST? Answer: determine whether the database or another safeguard covers loaded data.

2. A process commits a payment, fails before the bank acknowledges and retries. Which control BEST reduces duplicate payments? Answer: end-to-end transaction identity with reconciliation of exceptions.

3. Which evidence BEST supports detecting unauthorized actions by a database administrator? Answer: independent monitoring of audit logs covering sensitive DBA actions.
