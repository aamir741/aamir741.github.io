CISA Domain 5.8: Cloud and Virtualized Environments

CISA Domain 5.8: cloud versus virtualization, hypervisors, VLANs and SDN, containers, secure migration, shared responsibility, CSPM and CIEM.

Muhammad Aamir · 28 November 2026

A storage bucket is set to private. The provider has a clean assurance report. So is the data safe? Not if a forgotten automation identity can make it public. This lesson covers CISA Domain five, section 5.8: cloud and virtualized environments.

In this lesson

  • Cloud vs virtual: Two different ideas
  • Virtualization: Hypervisors, VLANs, SDN
  • Containers: And secure migration
  • Shared duties: Service models and assurance
  • Auditor view: Posture and entitlements

5.8 Cloud vs virtualization

Cloud computing provides network access to shared computing services that can be provisioned and released as needed. Common characteristics include self-service, shared resources, elasticity and measured use.

Exam Trap: A hosted server is not automatically the whole cloud model.

Cloud vs virtualization

  • Cloud: Shared services, provisioned as needed; Self-service, measured use
  • Virtualization: Abstracts resources; Many logical environments

Cloud characteristics

  • Self-service: Provisioned as needed
  • Shared resources: Pooled for many users
  • Elasticity: Scale up and down
  • Measured use: Pay for what is used

What Changes: Cloud changes where services run and how duties are divided.

5.8.1 Virtualization controls

Sections 5.8.1 to 5.8.3: virtualization and typical controls, virtual circuits and V LANs, and software-defined networking.

VMs and hypervisors

  • Virtual machine: A logical computer on shared hardware
  • Hypervisor: Creates and manages separation
  • Type 1: Runs on the platform
  • Type 2: Runs above a host O S

Virtualization controls

  • Admin access: And management A P Is
  • Images: Secure and maintained
  • Snapshots: May hold secrets and memory
  • VM sprawl: Inventory, owners, retirement

Hypervisor Risk: Hypervisor compromise can affect hosted workloads, but impact varies.

Exam Trap: A V LAN is logical separation. It is not encryption.

Software-Defined Networking: Central policy improves consistency, but concentrates risk.

5.8.4 Containers and migration

Sections 5.8.4 and 5.8.5: containerization, and secure cloud migration.

Protect containers

  • Image provenance: And registries
  • Build pipelines: And orchestration access
  • Secrets: Kept out of images
  • Privileged containers: Avoid unless necessary

Exam Trap: A scanned image does not prove the runtime configuration is safe.

VM vs container

  • Virtual machine: Own guest environment; Managed through a hypervisor
  • Container: Commonly shares the host kernel; Packages app and dependencies

Migrate securely

  • Inventory: Applications, data, dependencies
  • Assess: Suitability and risk
  • Design: Access, logging, encryption, exit
  • Test: Migration and operation

5.8.5 Shared responsibility

Now the shared responsibility model, cloud risk and assurance.

Service models

  • IaaS: Customer: guest O S, apps, data
  • PaaS: Customer: code, data, identities
  • SaaS: Customer: use, access, settings

Exam Trap: A contract is important, but does not replace customer access and configuration.

Cloud risks to assess

  • Tenant isolation: And management-plane access
  • Exposed storage: And data residency
  • Key access: Encryption and deletion
  • Exit: Continuity and data return

Contract Terms: Contracts should support incident cooperation, data return and deletion.

Soc 2: A S O C 2 report is not a universal certificate.

Devsecops: Infrastructure as code helps only when deployment authority is controlled.

Auditor perspective

Now the auditor perspective: cloud posture, entitlements and shared responsibility.

C S P M vs C I E M

  • C S P M: Assesses configurations; Against selected policies
  • C I E M: Examines effective entitlements; Inherited access, unused rights

Real-World Example: The bucket is private, yet an automation identity can make it public.

Inherited Access: Encryption is on, yet an inherited role can copy the data out.

Three cloud questions

  • Within baseline?: Posture tool coverage
  • Who can act?: Effective permissions
  • Any bypass?: Exceptions and alternate paths

Tool Limits: A tool's coverage and permissions must support the conclusion.

Outsourcing: Cloud outsourcing does not remove accountable risk decisions.

Practice questions

1. A storage bucket is configured as private, but a neglected automation identity can grant public access and disable logging. What should the auditor do FIRST? - A. Accept the private setting as evidence that the safeguard is effective - B. Review the configuration with the identity's effective authority - C. Rely on the provider's SOC 2 report as assurance for the bucket - D. Use a high posture-tool score to conclude the estate is secure Answer: B. A private setting can be reversed by an identity with enough authority; review configuration and effective authority together.

2. A company migrates its customer application to IaaS. Management states that the provider is responsible for all security controls. What is the auditor's BEST response? - A. Agree, because the contract transfers all responsibility to the provider - B. Agree, because a hosted server is the complete cloud service model - C. Disagree, because only the provider's facilities need to be reviewed - D. Map provider and customer duties, including guest systems and data Answer: D. Duties are shared; a contract does not replace the customer's access and configuration, so map provider and customer duties.

3. A container image passed a vulnerability scan before deployment. What should the auditor ALSO verify? - A. Runtime configuration, including privileges, secrets and network paths - B. That every container runs its own separate full operating system kernel - C. That the hypervisor in use is a type 1 rather than a type 2 - D. That the scan report was signed by the provider's SOC 2 auditor Answer: A. A scanned image does not prove the runtime configuration is safe; check privileges, secrets and network paths.
