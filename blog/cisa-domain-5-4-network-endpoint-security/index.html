CISA Domain 5.4: Network and Endpoint Security

CISA Domain 5.4: network infrastructure, VPNs, protocols, firewalls, the DMZ, proxies, endpoint security, EDR and XDR, and auditing effective network paths.

Muhammad Aamir · 28 November 2026

A diagram shows a subnet labelled D M Z. The firewall is new and the tunnel is encrypted. But is the network actually secure? This lesson covers CISA Domain five, section 5.4: network and endpoint security.

In this lesson

  • Network basics: Segments, NAC, VPN
  • Services: Protocols and local risks
  • Firewalls: Types, DMZ, proxies
  • Endpoints: EPP, EDR, XDR
  • Auditor view: Effective paths

5.4.1 Network basics and VPNs

Network and endpoint controls protect communication paths and the devices that use them. Map data flows, trust boundaries and management paths before evaluating any individual product.

Exam Trap: A permitted encrypted connection can still carry an unauthorized action.

Segment and control

  • Diagrams and owners: Know the whole network
  • Segmentation: By function and sensitivity
  • N A C: Identity and device posture
  • Management networks: As sensitive as business traffic

Not a firewall: NAT is not a firewall policy. A VLAN is not proof of filtering.

What a VPN needs

  • Cryptography: Strong, current protocol
  • Peer identity: And key or certificate lifecycle
  • Access scope: Routing and logging
  • Endpoint controls: The device still matters

AH vs ESP

  • A H: Integrity and origin; No confidentiality
  • E S P: Confidentiality if enabled; Plus integrity

Vpn Limit: A VPN does not make the remote device trustworthy.

5.4.3 Services and protocols

Protocol traps

  • HTTPS: Protects the connection only
  • FTP: Basic F T P doesn't encrypt
  • SFTP: A separate SSH-based protocol
  • Telnet: Changing the port adds no protection

Cdn and ntp: Never cache private responses under shared keys.

Local network risks

  • D H C P: Rogue servers redirect clients
  • S N M P: v1 and v2c lack confidentiality
  • R P C: Not inherently unauthenticated
  • A R P poisoning: False address mappings

Snmpv3: authNoPriv authenticates without encrypting. authPriv does both.

Real-World Example: A firewall purchase does not fix local-network trust.

5.4.5 Firewalls and the DMZ

Firewall types

  • Packet filtering: Addresses, protocols, ports
  • Stateful inspection: Tracks connection state
  • Application proxy: Mediates selected protocols
  • N G F W: Application awareness plus I P S
  • W A F: Web-focused rules

Features are not assurance: A W A F does not replace secure code or authorization.

DMZ and bastion

  • DMZ or screened subnet: Isolates public services
  • Bastion host: Hardened host at the boundary
  • One or more devices: Two firewalls aren't required

Exam Trap: Naming a subnet DMZ does not demonstrate isolation.

Source Routing: Disabling source routing does not stop every form of spoofing.

Utm and proxies: Convenience can concentrate failure.

5.4.7 Endpoint security

Endpoint layers

  • Secure baseline: Supported, patched, least privilege
  • Encryption: And host firewalls
  • Application control: Limit what can execute
  • Malware protection: Not limited to signatures

EDR vs XDR

  • E D R: Adds endpoint telemetry; Investigation and response
  • X D R: Correlates many sources; Endpoint, identity, network, cloud

Check both layers

  • Preventive: Configuration, patching, execution
  • Detective: Detection and response
  • Failure case: Telemetry lost, agent disabled

Product Labels: A product label alone does not establish protection.

Auditor perspective

Now the auditor perspective. Network security depends on defined trust boundaries, permitted traffic, managed devices, protected administration and monitoring.

Real-World Example: Web-to-database is restricted, yet an admin network reaches every database.

Inspect the real thing

  • Rules and groups: Firewalls, security groups
  • Routes: East-west and management paths
  • Authorized tests: Allowed and denied flows

Segmentation Test: Segmentation works only if the relevant paths enforce the boundary.

Ids and ips: An appliance outside the attack path gives little protection.

Practice questions

1. A diagram shows a subnet labelled DMZ for public web servers. What should the auditor do FIRST to conclude that it is actually isolated? - A. Confirm the diagram was approved by the network and security teams - B. Inspect the actual firewall rules, routing and the management paths - C. Confirm that the subnet name follows the naming standard for zones - D. Confirm that exactly two firewalls surround the subnet on all sides Answer: B. A diagram and a label show intent; only actual rules, routing and management paths show isolation.

2. Employees reach the network through an IPsec VPN from unmanaged personal laptops. What is the auditor's MOST significant concern? - A. Data is exposed in transit across the public internet - B. The VPN gateway lacks a scheduled firmware update - C. Any use of split tunneling is automatically unacceptable - D. A compromised device can act through a valid tunnel Answer: D. A valid tunnel does not make an unmanaged device trustworthy; a compromised endpoint can act through it.

3. Network devices are managed by SNMPv3 at the authNoPriv level across an untrusted segment. What is the auditor's PRIMARY concern? - A. Management messages are authenticated but not encrypted - B. Management messages are not authenticated at all - C. Community strings are used for the authentication of requests - D. Management sources cannot be restricted in SNMPv3 Answer: A. authNoPriv authenticates messages but does not encrypt them; authPriv provides both.
