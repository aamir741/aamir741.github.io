CISA Domain 5.7: Public Key Infrastructure

CISA Domain 5.7: public key infrastructure, certificates and components, validation and trust chains, key management, CRL and OCSP revocation, and PKI audit procedures.

Muhammad Aamir · 28 November 2026

A payroll site presents a valid certificate, signed by a trusted authority, for a completely different domain. The connection is encrypted. Should you trust it? This lesson covers CISA Domain five, section 5.7: public key infrastructure.

In this lesson

  • Certificates: And PKI components
  • Validation: Trust chains and names
  • Key management: Protect and recover keys
  • Revocation: C R L and O C S P
  • Audit: Policy, practice, evidence

5.7.1 Certificates and components

Public key infrastructure supports the trusted use of public keys, through certificates, validation and lifecycle processes. It answers one central question: why should a relying party believe that this key belongs to the claimed subject, for the intended purpose?

Exam Trap: A certificate is public. The private key must stay protected.

Who does what

  • C A: Issues and signs certificates
  • R A: Verifies applicants
  • Repository: Publishes certificates
  • Relying party: Makes the trust decision

Roles stay distinct: Roles may be combined, but accountability stays distinct.

Trust anchors

  • Trusted root: A trust anchor
  • Intermediate C A: Also issues certificates
  • Key pair: Use each key for approved purposes

A certificate is not a key: A certificate does not encrypt data by itself.

5.7.2 Validation and trust chains

Validate every part

  • Chain: To an accepted trust anchor
  • Signatures: And validity periods
  • Name: The intended service identity
  • Key usage: The right purpose
  • Status: Revocation policy applied

Exam Trap: A certificate is not acceptable merely because it has not expired.

Real-World Example: Encryption works, yet the server identity was never established.

Key Usage: A certificate must suit the purpose, not just the name.

Tls in practice: A certificate is not a session key, and it does not encrypt the conversation.

5.7.3 Key management

Key lifecycle

  • Generation: And enrollment
  • Storage and use: Protected and logged
  • Rotation and backup: Where appropriate
  • Destruction: At the end of life

Key controls

  • H S M: Protects sensitive keys
  • Separated duties: Dual control, split knowledge
  • Controlled renewal: Automation, not chaos

Encryption key vs signing key

  • Encryption key: Recovery may be essential; To restore business data
  • Signing key: Recovery or escrow has attribution risk; Needs deliberate policy

Expired Certificates: Without an inventory, certificates expire unnoticed.

5.7.4 Revocation

C R L vs O C S P

  • C R L: A signed list; Can be periodic
  • O C S P: A signed response; Can be cached

Exam Trap: Revocation does not erase a key or stop every use.

Status Outages: Check what the client does when status is unavailable.

After a compromise

  • Contain: Limit the exposure
  • Revoke: Affected certificates
  • Replace: Keys and certificates
  • Investigate: Affected use

Real-World Example: The new certificate is installed. The old one still validates.

5.7.5 Audit

Review the PKI

  • Identity proofing: And issuance approvals
  • Key protection: Plus trust stores
  • Status publication: And renewal
  • Logging: And recovery

C P vs C P S

  • Certificate policy: Rules and applicability; Permitted use
  • Practice statement: How the C A implements; Statement of practice

Exam Trap: A published C P S is not proof that every practice operated.

Trust Stores: Protect the trust store and who can change it.

Valid does not mean safe: A valid domain certificate does not prove the operator is honest.

Auditor View: Test validation at the point of use.

Practice questions

1. A payroll site presents a validly signed certificate, issued by a trusted CA, for an unrelated domain name. What should the auditor conclude? - A. The connection is acceptable because the chain is trusted and encrypted - B. The certificate is acceptable until its stated expiry date has passed - C. The issue is resolved once a stronger cipher suite has been selected - D. The intended server identity is not established despite the signature Answer: D. A trusted chain and encryption do not establish the intended server identity; the name mismatch defeats the trust decision.

2. A server's private key is compromised and a replacement certificate is installed, but the old certificate remains valid and trusted. What should be done FIRST? - A. Request revocation of the old certificate and assess relying parties - B. Wait for the old certificate to expire because the new one replaces it - C. Keep the old certificate in service since the new certificate is installed - D. Remove the old certificate from the repository to prevent its use Answer: A. Request revocation through the authorized process and assess relying-party checking; installing a new certificate does not retire the old one.

3. A certification authority publishes a certification practice statement. What should the auditor do to assess the CA's practices? - A. Accept the statement as proof that every described practice operated - B. Compare the statement's wording to the policy without testing operation - C. Obtain operating evidence that the described practices were followed - D. Treat the statement as unnecessary because the certificate chain is valid Answer: C. A published statement of practice is not proof that practices operated; obtain operating evidence.
